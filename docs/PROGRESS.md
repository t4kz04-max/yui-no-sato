## 起動・確認コマンド（PowerShell）

```powershell
npm install            # 初回のみ
npm run dev            # 開発サーバー → http://localhost:5173/
npm run typecheck      # TypeScript 型チェック
npm test               # 自動テスト（Vitest）
npm run build          # 型チェック＋本番ビルド（dist/）
npm run preview        # 本番ビルドの確認 → http://localhost:4173/
npm run test:browser   # ヘッドレス Chrome によるブラウザ動作確認（Chrome 必須、約20分。再開・橋の通行の確認を含む）
npm run test:bridge    # 橋の通行だけを確かめる（数分）
npm run test:preview   # 本番ビルドを vite preview で配信して確かめる（実際の操作だけで確認）
# 公開 URL で確かめる：$env:PREVIEW_URL="https://yui-no-sato.vercel.app/"; node scripts/browser-preview.mjs
npm run shots          # 見た目の確認用の撮影と描画負荷の計測 → test-results/shots-latest/
npm run check          # 型チェック＋自動テスト＋本番ビルド＋出力物の検査
```

GPU で描画負荷を測るとき：`$env:GPU="1"; npm run shots`（垂直同期を外して FPS を測る）。

## Phase 6（2026-10-15）：UI・音・演出・操作性の仕上げ（Beta 版）

**計画・結果：`docs/PHASE6_PLAN.md`**（実装前の現状確認と計画、§5 に結果・音の一覧・カメラと性能の計測）。状態の変更点は `docs/STATE_TABLE.md` §15。

### Completed
- **タイトル・スタートメニュー・ローディング**：起動中は「村を準備しています」。タイトル画面（はじめから／つづきから／設定／史実と創作について、基本操作の一覧、前回の記録の日時と章）。背景は村をゆっくり見回す。はじめから → 導入（第1幕・屋根葺きを控えた秋）→ 村へ。壊れた記録はタイトル画面で知らせる（別名で残すのは従来どおり）。
- **設定**：視点の感度・上下反転、音量（全体・音楽・環境音・効果音）、音を消す、会話の文字の速さ、操作の手引き、左下の操作一覧。端末に保存し、再起動後も反映（物語の記録とは別。壊れた値は既定値に戻す）。マウスでもキー（↑↓・←→・Enter・Esc）でも操作できる。
- **操作の手引き**：まだ行っていない操作を、役に立つ場面で一つずつ画面下に出す（歩く → 見回す → 目の前に人がいれば E で話す → 記録ができたら Tab で手帳 → 走る → Esc でポーズ）。行ったら二度と出さない。物語の情報は出さない。
- **ポーズ**：いまできること（目的）を表示。選んだことの記録・設定・タイトルに戻るを追加。低い画面では二列（文字は小さくしない）。
- **手帳**：新しい記録・更新された記録は全文、一度読んだ記録は要点だけにして全文は開閉式（同じ長文を何度も読ませない）。
- **重要な発見の意味**：情報を知って作業台で考えられる案が増えたときは「作業台：考えられる案が増えた」と一行添える（どの案かは言わない）。
- **作業台**：右上に「この案の要点」（いつ／屋根をどこまで／加わる人／負担が重くなる人／残る約束・返し）。知らない事情は「分からない」と出す。承諾を得た案が二つ以上あれば、要点を表で見比べる（正解の印はない）。くわしい見込みは開閉式。返事（相談が要る人・同意の状況）はその下。
- **計画の決定の時期の修正**：決めた時点では「段取りが決まった」（決めた段取り・準備が整ったこと・書き留めた約束）とだけ出し、「葺き替えられた」とは出さない。葺き替えの記録（手帳）は、屋根葺きの日にサエと話して「一日を終える」を選んだときに付く。屋根葺きの日の途中の古い記録は読み込み時に補正。

### 既存試作の調査結果

| 要素 | 試作の状態 | 対応 |
|---|---|---|
| 地形の起伏 | sin/cos による起伏。プレイヤーは常に y=0 | 高さ関数 `terrainHeight()` に切り出して移植。メッシュと接地で同じ関数を使用 |
| 合掌造り | 石垣・躯体・白壁・柱・障子・屋根 | 移植。屋根は約34°と浅かった（コメントは「60度近い」）ため、約58°の厚みのある切妻に作り直した |
| 光源・影・トーンマッピング | 午後の光、ACES | 移植（秋の光に色調整） |
| 木・山・灯籠・薪 | Math.random による配置 | 移植。シード付き乱数で毎回同じ配置に |
| プレイヤー | 笠をかぶった人型、足振り | 移植。股関節で回転する構造と速度連動アニメに改良 |
| 移動 | フレームごとの定数でフレームレート依存。**A/D が左右逆** | 経過時間ベースで作り直し、左右も修正 |
| 当たり判定 | **全建物の判定が原点付近に作られるバグ**（グループの行列更新前に `Box3.setFromObject`）。回転も未対応 | 配置データから回転付き矩形・円の2D判定を生成する方式に作り直し |
| カメラ | 球面座標の追従、ドラッグ・ホイール。補間がフレーム依存、壁抜けあり | 軌道計算を移植し、dt ベースの補間と壁抜け防止を追加 |
| ジャンプ | あり | 削除（設計書 F 節：ジャンプは必須機能としない） |
| その他 | 未使用の道 Shape、薪が道の上、ホイールでページスクロール、Tailwind CDN | 修正・不使用 |

### 技術的な判断

1. **全面破棄ではなく「移植＋再構成」**：見た目の構築コードは移植し、設計書 N 節で再設計対象とされた移動・当たり判定・カメラ・構造を作り直した。
2. **当たり判定は XZ 平面の 2D（回転矩形＋円）**：ジャンプのない探索ゲームのため 3D 物理エンジンは不要。描画と同じ配置データ（`world/layout.ts`）から生成し、見た目と判定のずれを防ぐ。
3. **状態と描画の分離**：`PlayerController`（純粋ロジック）→ `PlayerView`（見た目に反映するだけ）。カメラも `orbit.ts`（純粋計算）と `ThirdPersonCamera`（Three.js）に分離。
4. **移動はフレームレート非依存**：加速を解析的に積分し、30fps と 144fps で移動距離が一致する。dt は最大 0.1 秒に制限。
5. **視点操作はマウスドラッグ方式**：ポインターロックは会話・手帳 UI のクリック操作と衝突しやすいため見送り。
6. **描画負荷の削減（計測に基づく）**：初版の約 1,170 回の描画呼び出しを、木の InstancedMesh 化と静的メッシュの結合で約 96 回に削減。
7. **影は村全体を覆う固定範囲**（2048px）。
8. **Tailwind は不採用**。
9. **入力の抽象化**：ゲームはキーコードを直接見ず `MoveIntent`／`OrbitInput` を受け取る。
10. **座標系**：北 = -Z、南 = +Z、東 = +X、西 = -X。スタートは橋の南（0, 31）で北を向く。
11. **村の配置は仮**：主要地点を歩いて一周約 1 分。
12. **追加した依存**：`vitest`、`puppeteer-core`（いずれも開発用。`npm audit` 0 件）。

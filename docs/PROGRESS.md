## Phase 1 の設計（技術的な判断と理由）

1. **NPC と調査対象は共通の仕組み**（PHASE_PLAN §5 設計条件）：どちらも `Interactable`（位置・範囲・会話 ID）で定義し、E を押すと同じ `DialogueRunner` で会話データを進める。違いは種類（`npc`／`object`）による案内文言・カメラ・見た目だけ。
2. **会話内容はデータ（`src/content/`）に分離**：会話は「場面（ノード）＋ページ＋選択肢＋条件＋効果」の形式。3D 描画・UI のコードには台詞を書かない。会話の追加は `content/dialogues.ts` に1項目、配置は `content/interactables.ts` に1項目を足すだけ。
3. **会話データの自動検証**（`dialogue/validate.ts`）：参照切れ、最後の入口に条件がある（会話を始められない）、条件付きの選択肢しかない、抜け出せない循環、到達できない場面、未登録の話し手を検出。全会話データをテストで検査し、条件で使うフラグが実際に立てられるものかも検査する。将来シナリオが増えても進行不能を早く見つけられる。
4. **ゲーム状態は Phase 1 では「フラグ集合」だけ**（`story/StoryState.ts`）：会話・調査の結果を保持し、条件（flag／not／all／any）で会話・選択肢・目的を出し分ける。NPC ごとの状態・手帳・結帳・セーブは Phase 2 の範囲なので作っていない。`Condition`／`Effect` は種類を足せば拡張できる形にした。
5. **ロジックは DOM・Three.js 非依存**：`StoryState`・`DialogueRunner`・`InteractionSystem`・`targeting`・`areas` はすべて純粋な TypeScript で、Node 上の単体テストで検証している。`Game` が状態を読み、3D（`NpcView`・`InteractionMarker`）と UI（`DialogueBox`・`InteractionPrompt`・`Hud`）に反映する。UI はゲームロジックを直接操作せず、コールバック（送る・選ぶ）を返すだけ。
6. **文字送りの状態は UI 側**：表示上の演出なのでゲーム状態に含めない。決定キーは「文字送り中なら全文表示、そうでなければ進める」。
7. **人物モデルの共通化**：プレイヤーの仮モデルを `characters/personRig.ts` に切り出し、服の色・かぶり物（笠・手ぬぐい）・背丈で住民を見分けられるようにした。Phase 5 で本格モデルに置き換える前提。
8. **系統間はイベントで接続**：`StoryState` と `InteractionSystem` は通知先（`EventSink`）だけを受け取り、目的表示・地名表示・カメラ演出は `Game` がイベントを購読して行う。
9. **新しい依存ライブラリはなし**。

### 既存試作の調査結果

| 要素 | 試作の状態 | 対応 |
|---|---|---|
| 地形の起伏 | sin/cos による起伏。プレイヤーは常に y=0 | 高さ関数 `terrainHeight()` に切り出して移植。メッシュと接地で同じ関数を使用 |
| 合掌造り | 石垣・躯体・白壁・柱・障子・屋根 | 移植。屋根は約34°と浅かった（コメントは「60度近い」）ため、約58°の厚みのある切妻に作り直した |

| 木・山・灯籠・薪 | Math.random による配置 | 移植。シード付き乱数で毎回同じ配置に |
| プレイヤー | 笠をかぶった人型、足振り | 移植。股関節で回転する構造と速度連動アニメに改良 |
| 移動 | フレームごとの定数でフレームレート依存。**A/D が左右逆** | 経過時間ベースで作り直し、左右も修正 |
| 当たり判定 | **全建物の判定が原点付近に作られるバグ**（グループの行列更新前に `Box3.setFromObject`）。回転も未対応 | 配置データから回転付き矩形・円の2D判定を生成する方式に作り直し |
| カメラ | 球面座標の追従、ドラッグ・ホイール。補間がフレーム依存、壁抜けあり | 軌道計算を移植し、dt ベースの補間と壁抜け防止を追加 |
| ジャンプ | あり | 削除（設計書 F 節：ジャンプは必須機能としない） |
| その他 | 未使用の道 Shape、薪が道の上、ホイールでページスクロール、Tailwind CDN | 修正・不使用 |

### 技術的な判断

1. **全面破棄ではなく「移植＋再構成」**：見た目の構築コードは移植し、設計書 N 節で再設計対象とされた移動・当たり判定・カメラ・構造を作り直した。
2. **当たり判定は XZ 平面の 2D（回転矩形＋円）**：ジャンプのない探索ゲームのため 3D 物理エンジンは不要。描画と同じ配置データ（`world/layout.ts`）から生成し、見た目と判定のずれを防ぐ。
3. **状態と描画の分離**：`PlayerController`（純粋ロジック）→ `PlayerView`（見た目に反映するだけ）。カメラも `orbit.ts`（純粋計算）と `ThirdPersonCamera`（Three.js）に分離。
4. **移動はフレームレート非依存**：加速を解析的に積分し、30fps と 144fps で移動距離が一致する。dt は最大 0.1 秒に制限。
5. **視点操作はマウスドラッグ方式**：ポインターロックは会話・手帳 UI のクリック操作と衝突しやすいため見送り。
6. **描画負荷の削減（計測に基づく）**：初版の約 1,170 回の描画呼び出しを、木の InstancedMesh 化と静的メッシュの結合で約 96 回に削減。
7. **影は村全体を覆う固定範囲**（2048px）。
8. **Tailwind は不採用**。
9. **入力の抽象化**：ゲームはキーコードを直接見ず `MoveIntent`／`OrbitInput` を受け取る。
10. **座標系**：北 = -Z、南 = +Z、東 = +X、西 = -X。スタートは橋の南（0, 31）で北を向く。
11. **村の配置は仮**：主要地点を歩いて一周約 1 分。
12. **追加した依存**：`vitest`、`puppeteer-core`（いずれも開発用。`npm audit` 0 件）。

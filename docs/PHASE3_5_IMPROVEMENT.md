# Phase 3.5 改善計画：試遊フィードバックに基づくゲーム体験改善

**位置づけ：** PHASE_PLAN の正式な Phase ではなく、Phase 3（縦切り試作）と Phase 4 の間の品質改善作業（ユーザー指示 2026-10-14）。
**維持するもの：** 村の探索で事情を知る仕組み、結帳（試遊で好評）。返事は案の内容だけで決まる規則。過去の協力と現在の同意の区別。
**目標：** A 文字の読みやすさ／B 情報の整理と提示／C 計画に迷いが生まれること／D 選択の結果の違いを実感できること。

---

## 1. 試遊結果から推測できる問題

| 評価 | 推測 |
|---|---|
| 計画を変えたくなった：微妙 | 情報が「選択肢を増やす鍵」として働いており、「今の案の何が問題か」を考える材料になっていない |
| 計画に迷わなかった：いいえ | 全員が承諾した案がそのまま「正解」に見える。承諾を集めること自体が目的になっている |
| 結果の違いを感じた：微妙 | 結果の差が文章の中に埋もれ、村に戻っても変化がほとんど見えない |
| 文字が小さい・情報が多い | 小さい文字で、要点と詳細が同じ重さで並んでいる |

## 2. コードとシナリオで裏付けた問題

1. **R2 が「ご褒美の正解」になっている。** R2 に必要な選択肢（前日の準備・刈り入れの手伝い）は、最も深い2つの発見（伊助と詳しく話す・畑を二度調べる）で初めて出る（`content/plan.ts` の `when`）。最後に開いた案が最も皆に都合がよく見えるため、探索が「正解を開くパズル」になっていた。
2. **代償が文章だけ。** R2 の「約束が残る」、R3 の「屋根の傷みが進む」は、結果画面の文章と手帳の一行に出るだけで、判断の前には見えず、判断の後も村の様子が変わらない（変わるのは屋根の色だけで、全結果で共通）。
3. **判断の瞬間に比べるものがない。** 作業台は「今の案への返事」と「手帳の情報」を出すが、案ごとに何が起きるかの見込みを出していない（`journal/planModels.ts`）。決定できるのは今の案だけで、承諾を得た別の案と並べて選ぶことができない。結果として「全員が承諾した最初の案を決める」行動になる。
4. **サエの気がかりが判断を縛らない。** サエは「他家に負担をかけたくない」と言うが、どの案にも承諾する（延ばして伊助が来ない案を除く）。気がかりは台詞に出るだけで、作業台の判断材料として整理されていない。
5. **作業台の情報が関係の薄いものも含めて並ぶ。** 「考えておくこと」に、今の案と関係しない情報も同じ重さで並ぶ。
6. **文字が小さい。** 本文 13〜15px、補足 11〜12px が多い（CSS で 13px 以下が 43 か所）。手帳・作業台は要点と詳細が同じ見た目。
7. **結果画面が「何が変わったか」の一覧のみ。** 自分が決めたこと／実現したこと／残った負担が分かれていない。選ばなかった案との違いも見えない。

## 3. 改善案（Phase 3.5 で実施）

### A. 文字と画面
- 文字の大きさを全面的に見直す（本文 17〜20px、補足 14px 以上、会話 20px）。行間・余白・コントラストを上げる。
- 画面ごとに「見出し → 要点 → 詳細」の階層を作り、大きな画面（手帳・結帳・作業台・結果）は画面の高さに収めて中をスクロールさせる。
- 通知は最大2件に減らし、何が分かったかを短く示す。

### B. 情報の3段階（削らずに整理）
| 段階 | 例 | 置き場所 |
|---|---|---|
| 1 その場で必ず理解してほしい | 「伊助：予定日は刈り入れと重なる」 | 会話の強調、通知、手帳の要点、作業台の見込み |
| 2 判断のときに参照する | 情報の全文、住民の今の意向、案への返事 | 手帳の本文、作業台の「この案に関わる事情」 |
| 3 詳しく読みたい人向け | これまでの記録、入手元、結帳の関連情報 | 開閉式の欄 |

- 情報（トピック）の各段階に**要点**（短い一句）を追加し、手帳・作業台・通知で使う。全文は残す。
- 会話の重要な一句を強調表示する（`**…**`）。長い台詞は短くする。
- 作業台の「事情」は、今の案の選択肢に関係するものだけを出す（それ以外は手帳へ）。

### C. 判断に迷いが生まれるように
- **作業台に「この案で起きること（見込み）」を出す。** 屋根／伊助の刈り入れ／サエ家が負うこと／伊助の関わり方の4つの観点で、案の内容から決まる見込みを文章で示す（点数・記号にしない）。
  - **見込みは知っている情報の分だけ見える。** 例：屋根を調べていなければ「待つあいだ屋根がどうなるかは、まだ分からない」。探索は「正解を開く鍵」ではなく「結果を見通す力」になる。
- **承諾を得た案を並べて選べるようにする。** 承諾を得た案が複数あれば一覧に並び、見込みを見比べてから決める。決定の瞬間に「何を大切にするか」を選ぶ場面を作る。
- **代償を具体的にする（自然な事情から）。** R2：前日に伊助の刈り入れが半日止まる（天気が崩れれば稲が傷む恐れ）、屋根葺きの直後にサエ家が刈り入れに人を出す約束、十二年前の返しが残ったまま約束が重なる。R3：十日待つあいだに傷みが広がり、手間と茅が余計に要る（茅が足りるかはミネ次第＝Phase 4）。R1：人手不足で二日がかり、伊助は関わらない。R3'：サエ家は自分の屋根を後回しにして他家の田に出る。
- 新しいトラブルやパラメータは足さない。

### D. 結果の実感
- 結果画面を **「自分が決めたこと」「実現したこと」「その代わりに残ったこと」** の3つに分け、最後に **「承諾を得たが選ばなかった案」** を一行ずつ示す。
- **村の様子を結果ごとに変える（既存の3D空間を活用）。**
  - R2：サエが伊助の畑に出て刈り入れを手伝っている（約束を果たしている最中）。サエ家の前は空いている。
  - R3・R3'：刈り入れが済み、はさ掛けに稲がすべて掛かっている。伊助がサエ家の前に来ている。
  - R1：伊助は畑で刈り入れを続けている。サエは家の前。
  - 屋根の色（葺き替え後）は全結果で共通。

## 4. 改善しても残る問題

- 2人だけでは観点が限られ、判断の深さに上限がある（屋根・刈り入れ・約束・関わり方の4観点）。
- 見込みが見えることで「好みで選ぶ」場面は作れるが、どの観点を大切にするかを揺さぶる出来事は少ない。
- R2 の約束・R3 の返しが、その後どうなるかはまだ描けない（第3幕）。
- 返事の規則は決まっているので、往復すれば全組み合わせを試せる（往復の手間は残る）。

## 5. Phase 4 で解決すべき問題

| 問題 | Phase 4 での手当て |
|---|---|
| R3 の「茅が余計に要る」が言葉だけ | ミネの茅（設計書 H：P1・P2）を計画に組み込み、茅を借りる約束を伴わせる |
| 日程を変える案に宗平の都合が関わらない | 宗平の「動けない日」（設計書 H：P2）を計画の条件にする |
| 約束・返しのその後 | 第3幕（伊助家の屋根葺き）で、R2 の約束・R3 の返しを問う |
| 屋根葺き当日が文章だけ | 当日の村の場面（設計書 I） |
| 判断を揺さぶる観点が少ない | 宗平・ミネの事情が加わることで、観点（茅・段取り・別件の手伝い）が増える |

## 6. 文化的な解釈について

今回の変更では、結・合力の意味づけは変えない。結帳は「ゲーム用に創作した記録」のまま、過去の協力と現在の同意は別に扱う。見込みや結果の文章では、手伝いの「釣り合い」や「損得」を数値で示さない。
